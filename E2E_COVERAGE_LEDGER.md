### 4.1 Backend-only / dead-endpoint sweep (Phase 9, RUN-070)

Methodology: extracted the route + verb from all 295 canonical endpoint declarations, took each route's final path segment, and grepped `FrontEnd/src` (case-sensitive, then a fuzzy camelCase/hyphenated re-check) for any reference. 19 endpoints had zero literal-string hits; 10 were false positives on closer inspection (real callers using a differently-worded but equivalent frontend name). **9 confirmed to have no frontend caller anywhere in the codebase** — properly `auth = "user"`-gated backend logic that is simply unreachable through the product:

| Endpoint | Purpose (from source) | Note |
|---|---|---|
| `POST admin/vacation-mode` | Admin activates vacation/backup-admin handover mode | No admin UI control exists for this at all |
| `POST admin/backup-admin/designate` | Admin designates a backup admin account | No admin UI control exists |
| `POST admin/seasons/{id}/close-and-settle` | Closes a season and distributes final pioneer/manager shares | No admin UI; seasons can't be created anyway (TR-199), so moot for now but will matter once fixed |
| `POST admin/elections/{id}/voting-rights-price` | Sets the token price of election voting rights | No admin UI; same TR-199 dependency |
| `POST admin/sponsorships/{id}/recognize` | Grants a sponsor recognition badge/page-publish | `admin.ts` has `progress`/`refund` for sponsorships but never `recognize` |
| `POST contracts/applications/{app_id}/request-correction` | Giver requests the Taker correct/redo a submission before accepting/disputing | No frontend caller found in the Contracts feature |
| `POST education/sessions/{id}/verify/{enrollment_id}` | Teacher verifies a specific student's attendance/completion | No frontend caller found in Education/SessionDetail |
| `GET event_logs/logs/user/my_events` | Member's own activity/event log | No frontend caller — likely superseded by `wallets/me/activity` or `activity-rewards/activities/me`, but left orphaned rather than removed |
| `POST authentication/message/send_welcome_email` | Sends a canned welcome email | Not just orphaned — **also missing `auth` entirely**, filed separately as TR-216 (unauthenticated, spammable) |

None of these were exercised live this session (each would need either a fixture state that TR-199 currently makes impossible to reach, or would perform a real, non-reversible action against non-fixture backend state with no corresponding UI to verify the result through). Recommend Xano-side review of whether each is intentionally held back for a future release or is genuinely dead scaffolding to remove.

## 8. Accessibility, responsive, and cross-cutting sweeps (Phase 10, RUN-072)

**Responsive** — `/home` (as `E2E Adult C`/`VGC52`) screenshotted at 320, 360, 768, and 1280 CSS px. No horizontal overflow at any width (`document.documentElement.scrollWidth === clientWidth` confirmed at 320px); all cards/buttons/text reflow cleanly with no clipping or overlap. The app deliberately renders as a fixed-max-width mobile card centered with dark padding even at tablet/desktop widths (768/1280) rather than reflowing into a wider multi-column layout — this reads as an intentional mobile-first PWA design choice, not a defect, and is noted here rather than filed as a TR. 200% zoom not separately captured; treated as adequately covered by the 320–768px range already confirmed clean, since 200% zoom of a 1280px display is optically equivalent to roughly 640px, well inside the tested range.

**Accessibility (spot check, not full WCAG 2.2 AA audit)** — icon-only header controls ("Search", "Notifications" bell) both expose correct accessible names via the accessibility tree (confirmed via snapshot, not just visually); bottom nav (Home/Wallet/Explore/Community/Profile) is fully labelled. No missing-alt-text or unlabelled-control issues found in this spot check. A full automated WCAG audit (axe-core or equivalent) was not run — this is a targeted manual spot check only, not exhaustive.

**Security (extended)** — mass-assignment: grepped all 295 endpoints for the `data = $input` full-object-spread anti-pattern (an unfiltered write of the raw request body into a table) — zero matches; every write endpoint checked maps individual named fields, and Xano's typed `input {}` blocks additionally strip undeclared keys at the framework level (independently confirmed by TR-212's finding that an extra JSON key is silently dropped, never applied). IDOR: see WF-19/TR-217 above — one confirmed finding out of ~30 by-id endpoints checked. Rate-limiting: confirmed again (incidentally, during Gaming-screen testing) that at least one non-auth endpoint (`seasons/{id}/ledger`) is rate-limited under rapid repeated calls (`429`), consistent with TR-140's correction that rate limiting is real and not absent platform-wide as originally suspected.

**Deferred to a later session / requires hardware not available here**: full automated WCAG 2.2 AA audit tooling, physical-device QR/camera testing (education check-in, any mobile-native camera flows), true offline/PWA installability testing (service worker cache-hit behaviour under an actual network-drop), and a dedicated performance-profiling pass (Lighthouse/Web Vitals) — none of these are blocked by any defect found so far, they simply need tooling or hardware outside this local-dev browser-automation session.
